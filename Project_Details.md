# Project Details

## Next-Generation 9-1-1 Infrastructure Modernization & DevOps Knowledge Repository

**Organization:** Ontario Public Service - Emergency Health Services  
**Project Type:** Enterprise Technology / Knowledge Management Case Study  
**Role:** IT Analyst Intern  
**Duration:** May 2025 – December 2025

---

## 1. Project Background

Next-Generation 9-1-1 (NG9-1-1) represents a modernization of emergency
communications infrastructure designed to support evolving emergency
service requirements and more advanced routing and data capabilities.

As part of my Ontario Public Service internship with Emergency Health
Services, I contributed to a project supporting the modernization
environment through improved technical documentation and knowledge
management.

The project focused on making critical technical information easier to
organize, locate, understand, and maintain across teams involved in
technology implementation and troubleshooting.

---

## 2. Business Problem

Technical information required for system development, troubleshooting,
and modernization activities was distributed across multiple documentation
sources and legacy environments.

This created several challenges:

### Documentation Fragmentation

Technical schemas, data definitions, mapping information, and
troubleshooting procedures were not consistently organized in one
accessible location.

### Information Accessibility

Team members could spend significant time searching for the correct
technical reference or troubleshooting information.

### Data Definition Consistency

Different documentation sources created challenges in maintaining
consistent definitions and understanding relationships between data
elements.

### Troubleshooting

Root-cause analysis information and troubleshooting procedures needed a
more structured and accessible format.

### Cross-Team Communication

Internal technical teams and external vendors required access to
consistent technical information during system changes and upgrades.

---

## 3. Project Objectives

The project objectives were to:

1. Centralize important technical documentation.
2. Improve accessibility of technical knowledge.
3. Standardize data definitions and documentation.
4. Improve documentation of data relationships and lineage.
5. Organize troubleshooting procedures and runbooks.
6. Support more efficient issue investigation.
7. Improve communication between technical stakeholders.
8. Establish a maintainable knowledge-management structure.

---

## 4. My Contribution

As an IT Analyst Intern, I contributed to the analysis, organization,
documentation, and implementation of the knowledge-management solution.

My responsibilities included:

- Reviewing technical documentation and identifying information gaps.
- Organizing technical information into structured documentation.
- Supporting documentation of technical schemas and data definitions.
- Documenting data mapping relationships and lineage.
- Structuring troubleshooting and root-cause analysis information.
- Developing documentation workflows within Azure DevOps Wiki.
- Supporting integration with SharePoint Online.
- Working with stakeholders to understand documentation requirements.
- Improving consistency and accessibility of technical information.
- Supporting ongoing maintenance of technical documentation.

---

## 5. Solution

The project implemented a centralized knowledge repository using:

### Azure DevOps Wiki

Used as the primary structured knowledge environment for technical
documentation, including:

- Technical schemas
- Data definitions
- Data mapping information
- Troubleshooting procedures
- Root-cause analysis
- Technical runbooks

### SharePoint Online

Used to support centralized access to supporting documentation and
reference materials.

### Microsoft Visio

Used for visualizing workflows, processes, and technical relationships
where appropriate.
